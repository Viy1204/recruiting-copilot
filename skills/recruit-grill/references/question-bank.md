# 岗位梳理问题参考

按缺口选题，不按表逐项问完。前提已确定的问题可在同一轮提出；依赖本轮某个答案的问题，收到答案后再问。已确认的信息直接复用，AI 能拟定的寻源方案先拟，不让用户从零填写。

## 先定岗位目标和独立约束

| 要定什么 | 值得问的问题 | 怎么减少用户作答 |
|---|---|---|
| 存在意义 | 这个岗位要解决什么问题？ | 从业务资料提炼建议；背景不足时先问目标，不猜命脉。 |
| 核心交付物 | 半年内最重要的交付物是什么？ | 目标已明确就给一个可验证的产出建议；否则等目标确定。 |
| 定位 | 汇报给谁，是开荒还是补强？ | 组织资料已有就沿用；只确认缺失事实或角色边界。 |
| 地点 | 办公地、坐班要求、搬迁／远程接受度？ | 沿用已确认的公司口径，只问本岗差异。 |
| 薪资 | 带宽、薪数和可否突破？ | 已有预算不重问；没有依据就请用户提供或标待定。 |
| 门槛 | 学历、年限或其他限制是否为硬要求？ | 先复用 CONTEXT；新设门槛须明确依据和可否放宽，不自行新增年龄等限制。 |
| 优先级 | 相对其他在招岗位排在哪里？ | 从当前招聘安排拟建议，已明确则直接记。 |

这些是覆盖维度，不是必须逐个回答的表单。互不依赖、可一并确认的约束可合成一题；不要借合题暗藏尚未确定的前提。

## 目标确定后，定筛选依据

| 要定什么 | 值得问的问题 | 怎么减少用户作答 |
|---|---|---|
| 命脉 | 哪一项能力缺了，其他条件再好也不对口？ | 从已确认的目标和交付物提出最关键的 1–3 项，供整批调整。 |
| 硬底子与表层 | 哪些能力必须有，哪些行业／工具经验能补？ | 按 CONTEXT 方法论建议可放宽项；开荒与补强定位会影响深度／广度的取舍。 |
| AI 应用 | 是硬要求、加分项还是不看？ | 只在影响本岗交付时问；把“懂 AI”翻译成工作成果，不能默认一票否决。 |
| 验证 | 简历、作品集或面试中看什么证据？ | 命脉确定后由 AI 配验证信号；需要提交案例时一并确认形式。 |
| 排除信号 | 什么背景看着像、实际干不了？有明确禁区吗？ | 结合已知踩坑记录提建议；没有额外项可明确记“无”，不强凑反例。 |

## AI 先拟，不作为必答题

根据已确认标准，先拟目标公司／团队／赛道、首轮搜索词和渠道安排，说明与命脉的关联，标为“待寻源验证”。用户有指定来源、禁挖名单或渠道限制时纳入；未知就保留假设，不为凑公司数量或猜哪个平台池子更大拖住梳理。

## 收口检查

- 已能描述岗位目标、交付物和适用约束，命脉有验证信号，硬要求／加分项／排除信号分得清。
- 新增建议与冲突已由用户确认；明确答复只记一次，未答或“待定”不当同意。
- 缺失项会改变筛人结论或 JD 核心信息时，集中标出并保留草稿；搜索词效果等后续可验证项不阻塞。
- 用户只改一个条件时，只处理这个条件及其直接影响，不重启整套访谈。

提问节奏参考 Matt Pocock 的 [grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md)：一轮问齐前提已满足的问题，回答后再展开依赖项。`grill-me` 是其入口；招聘版以可执行标准为收口条件。
