# 招聘进展看板

先确认用户要看的工作区，定位本 skill 所在目录；读取该工作区的台账、岗位表、可选映射与独立进度文件。候选资料按点击读取，岗位状态仅在用户保存时更新本地岗位表。源码维护目录没有台账时，不自动创建候选资料或打开空面板。

## 打开与开工

Claude Desktop、Codex App、WorkBuddy 默认使用同一网页。先读取 [`references/hosts.md`](references/hosts.md)，按“读取现有事项 → 记录真实步骤 → connect 探测 → 必要时宿主管理前台服务并复核 → 打开或复用网页并交付本轮链接”交接，在耗时寻源前让用户看到本轮动态。首次默认打开 live 首页，明确指定本轮时才固定 run。只查看看板不 start；源码维护也不创建招聘 run。

只有 connect 返回 `ready` 才可复用服务；使用它返回的完整 `url` / `runUrl`，保留工作区键与 run 参数。宿主有专用服务、Browser/Preview 工具时使用实际工具，没有打开工具就给明确本机链接；不承诺自动右侧停靠。主 skill `/recruit-board` 提供同一个网页入口。原生注册已退役，已安装副本不会自动删除；按 hosts 中的停用与升级说明处理，不在本流程自动卸载。

## 读数边界

- 记录数只取 `02-sourcing/dedup-ledger.csv`，每个姓名＋原岗位计一次；同人不同原岗位不自动合并。阶段按当前状态精确映射。状态或评级冲突保留原值并归未归类，不从备注、档案或来源轮次推断。
- 岗位读取 `CONTEXT.md`「在招岗位与优先级」表。“在招”只含明确在招；“全部”保留各状态及未知岗位；“我的关注”是按工作区隔离的本机集合，可含任意状态，不修改 CONTEXT。选择关注使用独立面板，从全部岗位编辑，不受外层范围限制；岗位搜索只缩小选项，不改变汇总。切范围保留有效岗位选择，范围外选择清除并提示。未知岗位有可点击提醒，进入全部定位；只在台账出现的岗位说明来源，不假定可编辑。成功读取且全部确实在招才说明两个范围相同；缺失、错误、陈旧、未知和正常空表分别表达。
- 可选 `_shared/recruit-board.config.json` 以 `schemaVersion: 1`、`statusStages` 和 `roleAliases` 提供精确映射，格式见[配置参考](references/configuration.md)。状态键 trim＋英文小写，阶段值限 `STAGES` 中的 ID；岗位别名仅 trim 后完整匹配，目标须在本次成功读取的岗位表中，禁止链与循环。筛选用标准岗位名，原岗位仍显示；显式映射 `unclassified` 不报未识别状态。
- 无兼容配置时使用标准映射；首次配置非法则整份不应用并提示。曾成功应用的配置变坏或缺失时，候选、岗位与源时间整体保留并标陈旧，不能新旧混算。配置字典与说明元数据不进入 HTTP 快照。
- 上部是**工作区任务**，显示“任务类型 · 创建时间 · 可靠对象”；时间不同不追加 ID，同分钟仍重名时用简短序号，完整 ID 收入详情且身份不变。未绑定 session 的 run 不代表左侧会话本轮。网页常规首页默认 live，按 `createdAt` 跟随最新任务；带 `?run=<id>`（或 helper 完整链接中的 `run` 参数）明确固定本轮，手动选择历史也固定。查看候选、完整结果或编辑岗位时新 run 不抢占，保留阅读位置并提供“回到最新”。没有 run 时显示“尚无任务进度记录”，不补造历史。
- 前台每 1 秒单飞轮询，不重叠请求；页面隐藏时降频，恢复可见立即读取。读取状态与业务“最后记录”分开，轮询成功不能说明任务进程存活，也不称实时心跳；异常退出不按超时猜完成或失败。
- 总览、岗位人选、执行记录分别呈现。总览最多展示三条当前待回答摘要；没有待回答但有历史待核对时直接展示待核对。全部事项按岗位分组并保留待回答、历史待核对、已暂缓、后续执行和处理历史等筛选；组及组内按到期／阻塞当前事项、其他当前待回答、历史待核对排序，同级按等待时间稳定排列。仅真实期限或提醒时间产生到期判断，历史导入不制造紧急性。工作区总数不受轮次或岗位浏览影响；已决定但未落实仍可查，不要求重复回答。
- 近期重点按需读取已核实事件，默认近 7 天展示 3 条，超出三条有完整列表入口。先展示人选／对象及进展，再展示岗位、适用的核实细节和明确标注的更新时间；预约时段、发生时间和记录更新时间分别表达。桌面事项与进展两栏分别按内容定高，窄屏纵向。点击先进入事项或进展详情，再进入关联事项／人选资料；逐层返回恢复内容、筛选和列表位置，关闭恢复初始焦点，Esc 可退出，不叠多层弹窗。证据、来源和更正历史按需展开。无变化巡检不抹掉先前进展；未记录、读取失败和明确无变化分别提示，失败保留最后可信内容及时间。历史 run 保留原始事实，当前决定独立显示。
- 新记录的 `context`／`details` 见 [`references/decisions.md`](references/decisions.md#对象关联与事件细节)。旧事项可凭校验通过的来源 run＋result 引用恢复原人岗，不凭自由文本自动配人；关联不明标“关联待确认”，岗位不明归“岗位待确认”，明确工作区事项另组。原岗位关闭或候选已离开台账时仍保留原对象，资料缺失明确提示，不自动解决事项。
- 本轮逐人收据仍可从执行记录回看，独立于下方台账筛选。“本轮已记录 N 人”只表示收据覆盖数，未入账者不冒认资料。短结论和事项详情按需加载，不进入常规全量快照。演示只用隔离的虚构工作区；读写规则见 [`references/progress.md`](references/progress.md) 和 [`references/decisions.md`](references/decisions.md)。
- 全量快照仅含必要姓名、岗位、评级、原状态与阶段及任务 summary；结果短结论按需读取。点击候选后按原 ID 读取台账背景、备注、来源和已关联本地资料；资料正文不进入全量快照。不拖拽、不修改候选状态、不联系候选人，不连接 CDP、招聘网站或 DSH 面板。

## 候选资料与岗位管理

- 点击姓名查看资料，返回名单保留岗位、阶段和任务选择。仅支持工作区内 Markdown、TXT、PDF；Markdown 用安全文本元素显示，PDF 可独立打开或下载。外链、工作区外、可执行或不支持的文件明确标不可读。
- 台账简历路径按单个完整值解析，不拆分说明文字或猜附件。同名档案仅在姓名完整、全局唯一、姓名字段或标题一致、岗位精确匹配时自动关联；先核完整岗位名；完整值属于其他正式岗位或别名时绝不剥括号，只有未知尾注才可剥后精确核对。匹配档案的相对链接以档案目录解析。歧义可用 `_shared/recruit-board.files.json` 精确指定，格式见[配置参考](references/configuration.md#明确关联候选资料)；不扫描整个工作区找同名附件。
- 岗位旁“管理”只允许调整当前标准表中已配置岗位，状态限在招、已下架、已关闭、暂停、待核。保存更新本地 `CONTEXT.md` 的一个状态单元格，保留其他原文、换行和编码并自动备份；不修改招聘平台岗位。取消不写入，版本冲突时重新读取后再保存。
- `scripts/actions.mjs` 保留为共享 CLI，与网页共用资料解析和岗位写入；成功输出 JSON 数据，失败输出 JSON 错误并返回非零。`candidate`／`document`／`open-document` 只接原候选 ID 和资源 ID，`role-info` 读取版本，`role-set` 必须携带 revision。不能把任意路径或 shell 命令作为接口参数。

## 聊天处理事项

用户回答、暂缓、取消或修订旧问题时，读取 [`references/decisions.md`](references/decisions.md)，先获取当前事项及 revision，再按明确对象和范围记录决定。原 run 结束不影响处理，也不为一次答复新建完整招聘 run。答复存在歧义先消歧；点击查看、时间流逝和没有回应都不等于批准。

决定记录后同步实际需要更新的 `CONTEXT.md`、台账或档案；分别记录同步和执行结果。保存失败明确告知“同步未完成”；过期版本重新读取后核对，不覆盖新决定。面板和记录命令只保存事实，不执行平台动作，也不赋予额外授权。

## 工作流接入

执行初始化、岗位梳理、每日招聘、简历评估、约面试、人才盘点时，默认按 [`references/hosts.md`](references/hosts.md) 开工，并按 [`references/progress.md`](references/progress.md) 的 `WORKFLOWS` 记录真实进度。按 [`references/decisions.md`](references/decisions.md) 先读未解决事项与后续动作，主动与定时使用同一协议、标明实际来源；核实后及时记逐人 `result` 和重点 `highlight`，需要拍板的登记独立事项；新事项和重点填写已核实的 `context`，重点按需提供最多 8 项短文本 `details`，旧格式仍可读。结束 run 前写 `summary`。

只暂停依赖未决事项的动作，其他已授权工作继续；run 可以结束但独立事项不会消失。缺脚本或接入失败时说明未记录或看板不可用，继续不依赖该记录的招聘本体，不自动覆盖旧 skills；无法核实授权的动作等待处理。旧历史导入先归“历史待核对”，不把旧标记当成当前事实。
