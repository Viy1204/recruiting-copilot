# 看板配置与资料关联

看板从工作区读取 `CONTEXT.md` 的“在招岗位与优先级”表、`02-sourcing/dedup-ledger.csv` 候选台账与 `runtime/recruit-board/runs/` 任务记录。下列配置均为可选，文件放在用户的招聘工作区中。标准工作区无需添加配置。

## 兼容旧状态与岗位名称

固定文件 `_shared/recruit-board.config.json` 支持将旧台账中的状态映射到阶段，并为岗位设置别名。

```json
{
  "schemaVersion": 1,
  "statusStages": {
    "已沟通-待答复": "talking"
  },
  "roleAliases": {
    "旧岗位名": "标准岗位名"
  }
}
```

`statusStages` 按状态完整原值匹配，先去除首尾空白，再将英文字母转为小写。可覆盖标准映射。阶段值如下。

| 阶段值 | 页面名称 |
| --- | --- |
| `screen` | 待初筛 |
| `contact` | 待沟通 |
| `talking` | 沟通中 |
| `decision` | 待决策 |
| `interview` | 面试 |
| `offer` | Offer |
| `joined` | 入职 |
| `ended` | 已结束 |
| `unclassified` | 未归类 |

显式映射到 `unclassified` 表示该状态的阶段待核，不再作为未识别状态提示。

`roleAliases` 仅去除首尾空白后完整匹配。目标必须存在于本次成功读取的 `CONTEXT.md` 岗位表，禁止链式别名与循环。筛选使用标准岗位名，候选记录仍保留原岗位 `rawRole`，去重键不变。

配置任一字段非法时，整份配置不生效。首次读取失败时使用标准映射并提示；曾成功应用后文件变坏或消失时，整体保留上次候选、岗位与源时间，并标记陈旧，避免新旧数据混算。无配置时使用标准行为。可选说明字段 `description`、`verifiedAt`、`source` 不参与执行，配置字典和说明字段不进入 HTTP 快照。

## 明确关联候选资料

点击候选姓名时，看板按需读取台账背景、备注、来源与关联文件。资料正文、路径和文件映射不放入全量快照。

自动档案关联要求姓名完整且全局唯一，档案姓名字段或标题一致，并且岗位精确匹配。同名、打码姓名或岗位不明时不猜配。完整岗位值属于其他正式岗位或别名时，不能通过去掉括号将其归入当前岗位；只有未知尾注可去掉后再精确核对。

需要明确指定文件时，创建 `_shared/recruit-board.files.json`。候选 ID 是姓名与原岗位组成的 JSON 数组字符串，路径相对工作区。

```json
{
  "schemaVersion": 1,
  "candidates": {
    "[\"合成甲\",\"原岗位\"]": {
      "files": [
        {
          "path": "03-interview/合成甲.md",
          "label": "面试档案",
          "kind": "markdown"
        },
        {
          "path": "runtime/resumes/example.pdf",
          "label": "简历",
          "kind": "pdf"
        }
      ]
    }
  }
}
```

每条候选记录最多关联 30 份文件，`label` 和 `kind` 可以省略。仅开放工作区内的 Markdown、TXT、PDF；工作区外、外链、缺失和不支持的文件会提示不可读。档案内的相对附件链接按档案目录解析。台账简历路径按单个完整值读取，不拆分说明文字或扫描全工作区猜附件。

返回名单时保留任务、岗位和阶段选择。资料保持只读，不提供候选人外联操作。

## 保存本地岗位状态

岗位旁的“管理”支持在招、已下架、已关闭、暂停、待核，仅可调整当前标准表内已配置岗位。

保存只修改 `CONTEXT.md` 当前标准岗位表的一格状态，保留其他原文、换行及 UTF-8 或带 BOM 的 UTF-16 编码。原文备份到 `runtime/recruit-board/roles/`。取消不写入，版本或独占锁冲突返回 HTTP 409，需要重新读取后再保存。该操作不修改招聘平台上的岗位。

HTTP 保存限定同源 JSON 与会话令牌。原生面板使用 `scripts/actions.mjs` 的 `candidate`、`document`、`open-document`、`role-info`、`role-set`，与网页共用资料解析和岗位写入规则。

## 任务记录与缺失数据

任务状态与候选阶段是两组独立记录。任务的“本轮已记录 N 人”只统计本轮逐人结果覆盖的人数，按姓名与原岗位去重，不表示全部业务处理已经完成。岗位筛选不改变所选任务的结果。

没有任务记录时显示“尚无任务进度记录”。旧任务没有逐人结果时显示“未记录”。只有表头的台账是正常零条，未读取台账则是未知。状态或评级冲突保留原值并归未归类，不从备注、档案或来源轮次推断阶段，也不计算转化率。

开工、服务复用与宿主入口见[宿主接入说明](hosts.md)。逐人结果、待确认处理与六个工作流的映射见[共享进度协议](progress.md)。
