# 招聘工作台 Workspace 与宽窄布局验收

日期：2026-10-30。

实施依据为 [已确认方案](../docs/plans/recruit-board-workspace.md)，最初来源为本地设计 handoff。本记录对应合成工作区实施验收；只使用 `.audit/workbench-preview-zHdMjC`，没有导入真实岗位或候选人。后续用户授权的日常同步、真实验证与提交范围另见 [日常安装验证](workspace-layout-installed-checks.md)。

## 实现结果

- 主界面改称“招聘工作台”，保留现有暖灰、陶土强调色和浅深主题；主题 token 与实施前备份逐字一致。
- 新增 Workspace 主导航、关注岗位快捷入口、共用关注设置及工作区信息。同页定位使用稳定节点标识，执行记录导航保留历史任务。
- 搜索独立位于正文结构顶部，不参与排序；结果在岗位区显示，清空恢复原岗位与阶段。
- 宽屏三列且岗位最宽，中等宽度两列、确认与岗位在左及任务在右，窄栏单列。适配依据实际容器；编辑布局时临时单列。
- 明确零确认时变为紧凑跨行摘要，岗位与任务利用释放的列空间；未知、异常与陈旧不按零处理。
- 保留 `assistant / roles / tasks` 标识和 `layout:v1` 格式，因此旧记录中的确认区位置及子级顺序原样承接，无需清空偏好。
- 正式页自动适配；开发预览使用 `?preview=wide|narrow`，仅变更同一个容器的宽度，保留工作区和任务参数。

主要文件：`skills/recruit-board/public/index.html`、`app.js`、`style.css`。服务只额外允许合法的单个开发预览参数；模型、原生面板和类型文件哈希与本轮记录一致。

## 验证中修正

1. 首页旧标题断言仍要求“招聘进展”，改为验证正式“招聘工作台”标题。
2. HTTP实测 `?preview=wide` 最初400；服务白名单仅新增单个 `wide / narrow`，拒绝空值、重复值、其他模式及无关参数，并扩展公共测试。
3. 执行记录实际滚动目标是summary内h3，为该节点补滚动留白，实测不被吸顶栏覆盖。
4. 关注快捷入口最初清空阶段；移除该差异，与既有正文下拉行为一致。
5. 零确认标题保留可访问名称但不占视觉空间，紧凑摘要保持原排序位置。
6. 最后复核发现焦点恢复不应为正文按钮设置负tabIndex，已限定为标题；实测从侧栏设置缩窄到390px后，choose-following获得焦点且tabIndex仍为0。该修正后完成语法检查、实际页面复验及完整135项回归，全部通过；最后一次前台命令的结果另记于 `.audit/workspace-layout-20261030/final-check.md`。

## 技术结果与证据边界

- 基线完整测试：135通过、0失败；最终完整测试：135通过、0失败。中间一次因遗漏第二处旧标题断言失败，修正后复跑通过，未跳过或放宽业务测试。
- 开发预览服务IO测试：16通过、0失败，覆盖合法入口、非法/重复参数及原有工作区限制。
- `node --check`、`git diff --check` 通过；Git有既有LF转CRLF提示。
- 服务日志无错误；最终正常页面网络检查无失败请求。
- 浏览器日志中有故意注入坏偏好的告警；合成PointerEvent的setPointerCapture抛过NotFoundError，因为浏览器没有对应真实活动指针；另有调试canvas性能提示。这些均来自验收注入，不能将日志说成全程零错误，也未为消除模拟错误而修改业务指针代码。
- 首次仅element.focus()在无窗口焦点的预览里未派发focusin，之后通过显式事件模拟检验缩窄焦点路径；不能视为实体设备测试。
- 宽屏截图受宿主缩放影响，列宽和可读尺寸结论来自实际DOM与计算样式。没有实体手机触摸或完整辅助技术验收；岗位状态保存沿用原实现及回归测试，本次未操作真实工作区。
