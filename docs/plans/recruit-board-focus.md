2026-11-04：下文保留当时的范围决策；“不引入跨轮待办”的限制由 [ADR 0001](../adr/0001-cross-round-decisions.md) 和 [每轮重点与跨轮待确认方案](recruit-board-rounds-and-decisions.md) 调整。

## 本轮范围

- 首屏前置所选任务的“本轮需确认”名单，仅使用该任务原有 `attention=decision` 收据。默认展示少量人选，所有待确认事项仍可展开。
- 正常任务进度压缩，等待和失败原因保留可见；历史任务选择、逐人流水、处理数量和步骤默认折叠到执行记录。
- 候选阶段统计默认折叠，保留在招／关注／全部、岗位搜索、岗位管理和资料入口。
- 人选行保留姓名、岗位、原状态；详情中的背景与评估按需展开，附件入口保留。
- 网页与原生采用同样的展示顺序，沿用现有暖中性配色、字体、浅深主题。

不引入跨轮待办、期限判断、岗位风险、候选关注或面板向 Agent 发指令；不修改数据协议和业务事实。所选任务的确认记录不等于跨天未完成事项。

## 实现与并行边界

- 阻塞前置：已核对模型、确认收据语义、资料入口与已有截图；改前 `npm test` 130/130 通过。
- 独立工作流：网页负责人维护 public 三文件；原生负责人维护 hooks、状态类型和原生测试；主会话维护本文件、验证记录与合成验证场景。
- 共享状态：不修改共用模型或 API；不并发写相同文件。默认确认列表与手动展开状态分离，避免自动展示把实时跟随误固定。
- 最小分工：每个界面一个实现负责人，主会话复核状态、边界和实际网页；不增加独立任务系统或界面框架。

## 验证

1. 确认名单仅来源于所选任务，切任务不串人；同人多条待确认均可达；历史任务明确作用域。
2. 有确认、零确认、未记录、源失败／陈旧分别展示；消解确认后列表更新。
3. 默认折叠、不主动固定任务；用户阅读详情、依据或历史时保留阅读上下文。
4. 岗位范围／筛选、候选详情返回、原文与 PDF 入口、岗位管理仍可用。
5. 320px、窄侧栏与宽屏，浅深主题；检查控制台、网络、文字对比度和截图。
6. 项目回归、匹配宿主的原生行为测试与类型检查。原生实际绘制若受宿主限制，单独说明，不以网页或引擎测试代替。

全部使用虚构演示工作区。现有未跟踪材料保留，不提交、推送或更新真实工作区。
