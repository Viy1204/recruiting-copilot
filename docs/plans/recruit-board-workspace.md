# 招聘工作台 Workspace 与响应式布局

2026-10-30，用户逐项确认以下方案，并授权完整实现、同步日常安装副本，真实工作区验证通过后提交推送。最初参考为灰白工作台原型，本方案只沿用其导航与布局，保留正式页面现有配色。

## 已确认界面

- 主界面称“招聘工作台”，保留 Recruiting Copilot 品牌、暖灰表面、陶土强调色及浅深主题。
- Workspace 左栏包括招聘工作台、岗位与人选、执行记录三个同页定位入口，关注岗位快捷入口与设置，以及当前工作区名称和本地记录。
- 总览定位保留查询；岗位入口退出姓名搜索并恢复岗位阶段；执行记录展开并保持所选任务。关注岗位共用已有偏好，切换到关注范围和该岗位，阶段处理与正文下拉一致。
- 姓名搜索独立位于正文结构顶部，不参与排序，也不滚动悬浮。搜索结果替换岗位区，确认和任务仍可见；清空恢复原岗位与阶段。搜索始终覆盖全部岗位、全部阶段和历史岗位。
- 宽屏默认确认 / 岗位 / 任务三列，岗位区最宽；中等宽度默认确认与岗位在左、任务在右；窄侧栏隐藏Workspace并采用单列。适配按实际容器宽度，不按外窗判断嵌入侧栏。
- 窄栏默认顺序为工作台标题、搜索、确认事项、岗位与人选、任务与记录、数据详情；有用户排序时遵循保存顺序。
- 明确零确认压缩摘要并释放独占列；未知、读取异常与陈旧保持明确原因，不展示成零。
- 候选资料沿用触发区域原位置展开，关闭后保留查询、筛选、任务、阅读位置和焦点；依据和下载入口继续可用。
- 进入调整布局时临时单列，保留拖动、上下移、键盘确认取消和恢复默认；完成后恢复响应式布局。固定搜索和Workspace不参与排序。
- 正式页自动适配，手动宽屏 / 约390px窄栏切换仅在开发入口提供，同一份业务DOM和状态，不新增正式设备偏好。

## 兼容与实现边界

确认区沿用 `assistant` 排序标识及 `recruiting-board:layout:v1:<workspaceKey>` 格式，保留旧一级位置和岗位 / 任务子顺序。视觉顺序与键盘阅读顺序一致；异常存储降级保留提示。宽窄切换不重置查询、搜索已显示条数、岗位、阶段、任务、展开状态、资料来源和返回位置。导航重排后按稳定节点定位，轮询不抢焦点。

实现使用现有HTML、CSS、ES module及模型，不引入原型React/Babel或合成数据到正式运行时，不修改可选原生面板，不新增平台动作和后端数据模型。首页仅额外允许单个合法 `preview=wide|narrow` 参数，以提供开发验收入口。

## 验证

合成工作区覆盖零 / 六人确认 / 未记录 / 等待 / 失败等状态，并在320、375、390、768、960、1440px视口及宽浏览器内窄容器检查布局、状态、搜索、资料、排序与主题。日常安装副本只读验证真实加载、搜索、资料返回、岗位阶段、历史任务与布局，业务文件保持不变。
