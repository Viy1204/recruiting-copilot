# v0.7.0 正式版

v0.7.0 将 beta.2 的本地招聘进展看板纳入正式版本。网页集中展示本轮待确认人选、任务进度和逐人结果，并保留本地岗位管理与可选原生面板。主包、主插件和可选 `recruiting-board` 插件统一为 `0.7.0`。

## 本次交付

- 网页首页优先展示当前任务“本轮需确认”的人选、待拍板事项、资料与依据。同一人选的多条确认记录合并展示，人数按姓名和原岗位去重，岗位筛选不改变当前任务的确认名单。
- 六个执行流程记录实际步骤、等待、任务动态与逐人结果。页面支持跟随最新任务、固定历史任务，以及查看完整处理名单；没有记录时明确显示“未记录”，不补造历史。
- 候选阶段来自工作区台账和岗位表，支持在招、关注、全部范围，以及旧状态和岗位别名的显式映射。候选资料按需打开工作区内 Markdown、TXT、PDF。
- 岗位管理支持保存本地岗位状态，提供取消、冲突检测和原文备份。保存只修改 `CONTEXT.md` 当前标准岗位表的一格状态，不改变招聘平台上的岗位。
- 网页是 Claude、Codex App、WorkBuddy 的统一入口。支持 function hooks/Pane 的 Claude 宿主可手动打开 `/recruiting-board` 原生面板，同一插件只从一个来源加载。
- 保留跨 Agent 注册：Codex、Claude Code、Qoder 的项目级入口指向工作区同一份 `skills/`；其他工具可从 `AGENTS.md` 路由。

看板处理本地记录，不执行招聘平台操作。打招呼、拒绝、邀约、发送消息、发 offer 等对外动作仍按工作区规则先获确认，本版不扩大外联权限。

## 固定版本安装

需要 Node.js ≥22，以及支持 `AbortSignal.timeout` 和 `AbortSignal.any` 的现代浏览器。依赖安装器也以 Node.js 22 为最低版本。

通用 Agent 用户克隆固定标签后安装依赖：

```bash
git clone --branch v0.7.0 --depth 1 https://github.com/Viy1204/recruiting-copilot.git
cd recruiting-copilot
sh skills/recruit-init/scripts/install-dependencies.sh
```

首次用 AI 工具打开源码目录，说“帮我初始化招聘工作区”。日常招聘继续在独立的招聘工作区进行。

Claude Code 用户先查看现有 marketplace 来源：

```bash
claude plugin marketplace list --json
```

没有同名 `recruiting-copilot` 来源时，添加固定源码并安装主插件：

```bash
claude plugin marketplace add "/绝对路径/recruiting-copilot"
claude plugin install recruiting-copilot@recruiting-copilot
```

已有同名来源时，先确认该来源指向本次固定版本，再按原来源更新。单次会话也可直接加载固定源码：

```bash
claude --plugin-dir "/绝对路径/recruiting-copilot"
```

原生面板可选。宿主支持且没有从工作区重复加载时，可从同一个 marketplace 安装 `recruiting-board@recruiting-copilot`，或在单次会话增加 `--plugin-dir "/绝对路径/recruiting-copilot/skills/recruit-board"`。

DeepSeek Harness 使用固定 Git 标签安装：

```bash
dsh plugin --profile web add git+https://github.com/Viy1204/recruiting-copilot.git#v0.7.0
```

重新打开对应宿主会话后加载新版本。Release 源码 ZIP 包含主插件 `.claude-plugin/` 与 `commands/`，可作为 Claude marketplace 源码。TGZ 是用于 DSH 和脚本的打包资产；DSH 安装入口仍为上述 Git 来源，本次不以 npm 发布 recruiting-copilot。TGZ 不替代完整的 Claude 插件源码 ZIP。

## Boss CLI 依赖

安装器默认来源固定为：

```text
@viyzhu/boss-cli-fork@0.8.5
```

默认从 npm 安装该维护包，不再依赖内测 git 标签。保留 `BOSS_CLI_SOURCE` 覆盖；若指定带 ref 的 git 来源，安装器仍先克隆、构建并打包，再安装持久化包文件。

Boss fork 0.8.5 包含以下行为：

- 修复隐藏页面下 `search --city` 输入挂起。城市筛选仍要求完全匹配，失败不会自动改成全国搜索。
- 将搜索响应与本轮搜索快照绑定，并校验候选定位，避免沿用旧搜索结果操作人选。
- 提供显式 `boss reload`，刷新当前已登录主壳并作废旧搜索快照。刷新后重新执行原只读查询，不自动重做打招呼或发送操作。
- 在线简历 OCR 默认关闭。需要 OCR 时，显式设置 `BOSS_RESUME_OCR=1`，并配置百度 `BOSS_BAIDU_API_KEY` 与 `BOSS_BAIDU_SECRET_KEY`，或兼容的 `API_KEY` 与 `SECRET_KEY`。开启 OCR 会将简历截图发送至百度 OCR 服务。

仅更新依赖时，在固定版本源码目录运行安装脚本。它同时检查或安装猎聘 CLI；`--check-only` 只输出诊断，不安装包或修改 shell 配置。

## 升级已有工作区

更新源码或插件不会自动替换工作区 `skills/`。先备份工具文件和定制说明，再把本版工作流与 `skills/recruit-board/` 同步到工作区。由 beta.2 升级时，也要同步 `recruit-init` 的安装器和依赖说明。

保留已有 `AGENTS.md` 的定制路由，只补缺失的看板路由。需要补项目级发现入口时运行注册脚本，它保留并报告冲突项：

```bash
sh "/绝对路径/recruiting-copilot/skills/recruit-init/scripts/register-workspace-skills.sh" "/绝对路径/你的招聘工作区"
```

不要用初始化模板覆盖 `CONTEXT.md`、候选台账、JD、面试档案、定时预算或业务 `runtime/`。原生插件保持单一加载来源，重开宿主会话后加载新版本；已打开的网页刷新静态资源。

启动网页和核验工作区的命令见 [README 看板说明](../../README.md#本地招聘进展看板v070-正式版)，宿主打开方式见 [三端打开约定](../../skills/recruit-board/references/hosts.md)。

## 回退与兼容边界

停止本版看板服务，恢复升级前固定版本和工具备份，并重新打开宿主会话。持久安装的插件按原 scope 恢复来源与版本。候选台账、JD、档案和新增业务记录保留。代码回退不会撤销已保存的岗位状态；如需恢复，先核对 `runtime/recruit-board/roles/` 的备份，仅恢复目标状态。

网页依赖本机 Node 与前台 HTTP 服务。原生面板使用早期宿主 API，能否运行以对应宿主版本实测为准。beta.2 的历史验证见 [beta.2 说明](v0.7.0-beta.2.md)，不能替代正式版或所有宿主的验收。

正式版测试与发布边界见 [v0.7.0 验收记录](../../verification/release-v0.7.0-checks.md)。正式交付前核验固定 Boss 包可安装，以及源码 ZIP 与 TGZ 的版本、依赖和文件范围。
