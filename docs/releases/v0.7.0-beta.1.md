# v0.7.0-beta.1 测试版

本版本把本地招聘进展看板与六个招聘工作流一同交付，供固定版本试用。GitHub Release 标记为预发布；正式版仍为 `v0.6.6`。试用一周不需要持续追踪功能分支，以 `v0.7.0-beta.1` 标签为准。

## 本次变化

- 新增本机网页看板：查看工作区任务步骤、等待、最近处理记录、逐人结果与待确认事项；支持跟随最新任务或固定历史任务。
- 从现有台账与岗位表展示各岗位候选阶段，支持在招、关注、全部范围，以及旧状态与岗位别名的显式映射。
- 候选资料按需打开工作区内 Markdown、TXT、PDF；岗位管理可保存本地岗位状态，带冲突检测和原文备份。
- 初始化、岗位梳理、每日招聘、简历评估、约面试和人才盘点默认记录真实进度，并按宿主能力打开或复用网页。
- 提供可选 Claude 原生面板 `/recruiting-board`；网页是通用入口，原生能力依赖宿主版本。

候选状态仍由招聘流程核实后更新台账，看板不联系招聘平台。岗位“保存”只改本地 `CONTEXT.md`；打招呼、拒绝、邀约等动作继续沿用原确认规则。

## 固定版本安装

需要 Node.js ≥22，以及提供 `AbortSignal.timeout` / `AbortSignal.any` 的现代浏览器（Chrome／Edge 116+，Firefox 124+，Safari 17.4+）。单独克隆一份测试版，避免改变已有正式版目录。在要保存源码的目录执行：

```bash
git clone --branch v0.7.0-beta.1 --depth 1 https://github.com/Viy1204/recruiting-copilot.git recruiting-copilot-beta
```

源码/通用 Agent 用户用工具打开 `recruiting-copilot-beta`。首次使用可说“帮我初始化招聘工作区”；日常招聘仍在独立工作区进行。

Claude Code 用户先查看现有 marketplace 来源：

```bash
claude plugin marketplace list --json
```

没有同名 `recruiting-copilot` 来源时，可以添加固定源码为本地 marketplace 并安装；将占位路径替换为刚克隆的绝对路径：

```bash
claude plugin marketplace add "/绝对路径/recruiting-copilot-beta"
```

```bash
claude plugin install recruiting-copilot@recruiting-copilot
```

已有同名来源时，跳过上面两条持久安装命令，不要把另一份缓存当成已升级。可在单次会话中直接加载固定源码：

```bash
claude --plugin-dir "/绝对路径/recruiting-copilot-beta"
```

原生面板可选；仅在宿主支持 function hooks/Pane 且没有从工作区重复加载时使用。**只有确认同名 marketplace 来源是本次 beta 目录时**才执行：

```bash
claude plugin install recruiting-board@recruiting-copilot
```

若保留了已有同名 marketplace，单次会话同时加载 beta 主插件与原生插件：

```bash
claude --plugin-dir "/绝对路径/recruiting-copilot-beta" --plugin-dir "/绝对路径/recruiting-copilot-beta/skills/recruit-board"
```

`--plugin-dir` 对同名非受管安装有会话内优先级，无须停用正式版；组织受管插件按宿主管理要求处理。

DeepSeek Harness 用户可固定 Git 标签安装：

```bash
dsh plugin --profile web add git+https://github.com/Viy1204/recruiting-copilot.git#v0.7.0-beta.1
```

重新打开对应宿主会话后使用新版本。GitHub Release 同时提供源码 ZIP 和 npm 包；ZIP 包含主插件及命令，npm 包用于 DSH/脚本，不作为 Claude marketplace 源码的替代。

## 已有招聘工作区

更新源码或插件不会自动替换工作区已有的 `skills/`。本次发布也不会写入真实工作区。

升级前先把工作区 `skills/` 与 `AGENTS.md` 备份到独立位置。检查本地定制后，将测试版同名 skills 更新到工作区并加入 `skills/recruit-board/`；保留现有 `AGENTS.md` 的定制路由，只补入看板路由。不要用初始化模板覆盖 `CONTEXT.md`、台账、JD、档案或 `runtime/`。

如需补充项目级发现入口，使用已有注册脚本；它保留冲突项并报告：

```bash
sh "/绝对路径/recruiting-copilot-beta/skills/recruit-init/scripts/register-workspace-skills.sh" "/绝对路径/你的招聘工作区"
```

Windows 需要可创建符号链接的环境；没有该能力时仍可从工作区 `AGENTS.md` 路由到 `skills/`，不要把链接创建失败当成安装成功。

## 先打开看板

在固定版本源码中运行，路径指向真实招聘工作区；此命令只读数据并启动本机服务，不创建招聘任务：

```bash
node "/绝对路径/recruiting-copilot-beta/skills/recruit-board/scripts/server.mjs" --workspace "/绝对路径/你的招聘工作区" --port 4318
```

用另一终端核验工作区并取得完整链接：

```bash
node "/绝对路径/recruiting-copilot-beta/skills/recruit-board/scripts/connect.mjs" --workspace "/绝对路径/你的招聘工作区"
```

打开返回的 `url`。服务只在本机监听，由前台终端或宿主管理，关闭服务后页面不再更新。端口冲突时不停止其他工作区服务，另选端口，并给 connect 传相同的 `--url`。Claude Desktop 中由可用的 Preview 工具管理服务，详见 [宿主接入约定](../../skills/recruit-board/references/hosts.md)。

新任务进度要由升级后的工作流实际写入。历史记录没有进度或逐人结果时，页面会明确显示“未记录”，不会反推补造历史。

## 一周试用重点

- 每日招聘、简历评估是否在实际处理时更新步骤和逐人结果，需拍板事项是否正确保留并消解。
- 在招、关闭、暂停与别名岗位的候选人数是否与台账一致，重名/重复/冲突是否按原记录展示。
- 候选资料是否关联正确，返回列表和切换历史任务后筛选是否保留。
- 如试用岗位管理，核对只改变预期的一格状态，并保留 `runtime/recruit-board/roles/` 中的备份。

反馈时提供操作、预期、实际结果和宿主/版本；截图或日志中的真实姓名、联系方式与简历正文请先脱敏。

## 回退

停止 beta 看板服务，按安装方式回退：

- 源码或 `--plugin-dir` 单次加载：结束测试会话，下次使用原正式版目录且不带 beta 加载参数。
- 持久安装 Claude 插件：在原安装 scope 卸载 beta 主插件及可选原生看板，恢复原 marketplace 来源与固定 `v0.6.6` 源码，再安装正式版并重新打开宿主。不要仅切换源码目录，否则持久安装的 beta 仍可能加载；不要删除其他 scope 的 marketplace 配置。
- DeepSeek Harness：移除 beta 插件后，重新添加固定 `v0.6.6` 的 Git 来源并重开会话。

若升级过工作区 skills，恢复升级前备份与对应 AGENTS 路由。若 `recruit-board` 是本次新增，同时移除该目录及本次新建的 `.agents/skills/recruit-board`、`.claude/skills/recruit-board`、`.qoder/skills/recruit-board` 入口；只处理本次新增项，保留原有内容。不能仅覆盖式复制旧 skills 而留下 beta 发现入口。候选台账、JD、档案及业务数据保留。

若在看板里保存过岗位状态，代码回退不会撤销该业务变更；先查看对应备份，仅在确认需要时恢复目标状态，不用旧整份 CONTEXT 覆盖试用期间的其他更新。新增进度文件可保留，旧版本不会依赖它们。

## 发布验证

本轮完整 Node 回归 130/130、原生 2.1.299 引擎交互回归 41/41 通过；安装脚本与 WSL 工作区注册回归通过。实际发行包解包后已验证六类工作流命令，网页用合成工作区完成候选资料、进度等待消解与岗位保存恢复。详细结果与未验证项见 [发布验收](../../verification/release-v0.7.0-beta.1-checks.md)（源码 ZIP／Git 标签提供）。

## 版本边界

网页依赖本机 Node 与前台 HTTP 服务。原生面板使用早期宿主 API，其他版本能否运行以该宿主实测为准；网页、文件协议和 CLI 是通用试用路径。此次发布未重新实机验证原生新版布局或 Codex App、WorkBuddy 内打开；不声称已经完成一周生产验证，也不把历史本机验收等同于所有宿主兼容。
