# v0.9.0 正式版

v0.9.0 升级了招聘工作区的数据与上下文架构，将热状态与只追加冷日志分离，引入不可变岗位代理键 `role_id`、看板宽容读取与四组确定性工作区 CLI，降低长会话上下文膨胀与弱模型手改文件出错的风险。主包和主插件版本同步设为 `0.9.0`，默认 BOSS CLI 保持 `@viyzhu/boss-cli-fork@0.8.10`。

## 本次交付

- **宽容读取与七列岗位总表（[`model.mjs`](../../skills/recruit-board/model.mjs)）**。新增 `parseRoleStatus`、`readRoleTable` 与共享状态常量。读取老工作区带括号备注的状态（例如 `在招（2026-11-09 恢复）`）时，自动按前缀识别为 `在招` 并发出 `info` 级 `ROLE_STATUS_ANNOTATED` 提示，未迁移的老工作区更新代码后即可恢复显示全部在招岗。
- **确定性岗位表写命令（[`roles.mjs`](../../skills/recruit-board/scripts/roles.mjs)）**。新增 `list`、`set-status` 和 `upsert` CLI 子命令，支持按 `role_id` 或岗位名更新纯枚举状态与 `最近变更` 列，并自动向 `docs/CHANGELOG.md` 追加留痕。保留原并发锁、编码与换行保留及原文备份行为。
- **确定性台账查重与写入命令（[`ledger.mjs`](../../skills/recruit-board/scripts/ledger.mjs)）**。提供 `statuses`、`lookup`、`upsert` 三条命令。保持 9 列 CSV 与原 `candidateId` 结构不变，写入边界强制按 `role_id` 解析标准岗位名、校验 17 个通用标准状态、跨 `roleAliases` 自动查重、对已映射终态及未映射历史终态前缀（如 `已排除-*`、`初筛不合适-*`）执行退出码 `3` 拦截，写前过 `parseCSV` 复验并备份原子落盘。
- **单岗上下文切片与幂等迁移校验（[`role-context.mjs`](../../skills/recruit-board/scripts/role-context.mjs)、[`workspace.mjs`](../../skills/recruit-board/scripts/workspace.mjs)）**。`role-context.mjs` 按目标岗组装最小热包，并对未拆分的旧多轮关键词表自动只保留最近 2 轮。`workspace.mjs` 提供 `validate`（检查枚举、指针、体积红线、未映射台账状态 `UNMAPPED_LEDGER_STATUS` 与旧版 `AGENTS.md` 告警 `LEGACY_AGENTS_MD`）与幂等 `migrate`（支持 `--dry-run`、写前备份、预校验、自动生成 `role_id` 与拆分括号状态，重复执行零改动）。
- **模板、全工作流与架构决策同步**。更新 `recruit-init`、`recruit-daily`、`recruit-grill`、`resume-review`、`market-talent-mapping`、`recruit-board` 六组文档、初始化模板（新增 `CHANGELOG.md` 模板与热词卡片结构）及 [ADR 0007](../adr/0007-state-log-separation-and-deterministic-workspace-cli.md)。

## 固定版本安装

需要 Node.js ≥22、本机 Chrome 或 Edge，以及相应招聘平台账号。

```bash
git clone --branch v0.9.0 --depth 1 https://github.com/Viy1204/recruiting-copilot.git
```

进入源码目录后，运行依赖安装器。

```bash
sh skills/recruit-init/scripts/install-dependencies.sh
```

DeepSeek Harness 使用以下命令安装：

```bash
dsh plugin --profile web add git+https://github.com/Viy1204/recruiting-copilot.git#v0.9.0
```

GitHub Release 提供源码 ZIP、TGZ 与 SHA256 校验和。本版本不向 npm 发布 recruiting-copilot。

## 升级已有工作区

已有工作区无需重建目录或重写业务数据，按以下三步平滑升级。

1. 同步工作区的 `skills/` 文件（含 `skills/recruit-board/scripts/` 新增的 `ledger.mjs`、`role-context.mjs`、`workspace.mjs`），并确认 `.agents/skills/`、`.claude/skills/`、`.qoder/skills/` 指向最新副本。同步时保留业务文件（`CONTEXT.md`、`02-sourcing/dedup-ledger.csv`、`01-jd/`、`03-interview/`、`runtime/`）。
2. 先预览幂等迁移方案，再执行迁移与校验（严禁让 AI 手工改写长版 `CONTEXT.md`）：

```bash
node skills/recruit-board/scripts/workspace.mjs migrate --workspace "<你的工作区路径>" --dry-run
node skills/recruit-board/scripts/workspace.mjs migrate --workspace "<你的工作区路径>"
node skills/recruit-board/scripts/workspace.mjs validate --workspace "<你的工作区路径>"
```

3. 逐项处理 `validate` 输出的升级告警：
   - 若提示 `UNMAPPED_LEDGER_STATUS`，把历史自由文本状态补入 `_shared/recruit-board.config.json` 的 `statusStages`（不改台账原文）。
   - 若提示 `LEGACY_AGENTS_MD`，将工作区 `AGENTS.md` 中的岗位与台账操作入口指向 `skills/recruit-board/scripts/`，并清理与 `CONTEXT.md` 重复的硬规则。

若需要同步升级 BOSS CLI，运行：

```bash
npm install -g @viyzhu/boss-cli-fork@0.8.10 --registry=https://registry.npmjs.org/
```

## 回退与兼容边界

主插件或源码可随时切回 `v0.8.5`。9 列 `dedup-ledger.csv` 结构、原 `candidateId` 键、`_shared/recruit-board.config.json` 格式和 `runtime/recruit-board/` 数据均保持向后兼容。`workspace.mjs migrate` 改写 `CONTEXT.md` 前会在 `runtime/recruit-board/roles/` 保存逐字节原文备份，需要时可直接还原。

## 使用边界

本次更新不增加任何招聘平台外发或拒绝操作授权。四个新增确定性脚本只读写本机工作区文件，不连接招聘网站或浏览器，且全部强制工作区路径边界与符号链接检查。
