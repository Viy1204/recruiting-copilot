# ADR 0003：单网页看板与可追溯的对象信息

日期：2026-11-04

状态：已接受。用户已批准[信息清晰度与单网页维护方案](../plans/recruit-board-clarity-and-web-only.md)。沿用 [ADR 0001](0001-cross-round-decisions.md) 的跨轮事项、决定与执行分离和聊天决策入口，沿用 [ADR 0002](0002-board-progressive-disclosure.md) 的三个视图、渐进展开与阅读位置保护。

## 背景

同一招聘看板曾同时维护网页和 Claude 原生面板，带来重复的注册、界面和宿主验收工作。两套界面共享模型和脚本，原生退役不能连带删除公共能力。现有进展和事项还过多依赖自由文本，用户难以直接识别人选、岗位与事件细节；“在招”混入未知状态，个人关注选择与外层范围容易混淆。

## 决策

1. **只维护一个网页界面**：所有 Agent 使用同一网页 Skill、连接协议和前台服务。宿主按实际能力打开或复用网页；没有打开工具时交付已核验的完整本机链接。移除 `recruiting-board` 独立 marketplace 项、嵌套插件清单、原生 hooks、宿主专用测试、类型扩展、探针和预览同步。主招聘插件、网页资源、共享模型／类型、资料与岗位 actions、任务／事项记录脚本继续保留。
2. **对象信息与事实同时记录**：新重点和事项在对象已经核实时填写可选 `context`，区分 candidate、role、workspace。候选使用姓名＋原岗位的规范 JSON 字符串作为 `candidateId`；岗位事项明确 `role`；工作区事项不附人岗。重点可有最多 8 项单行短文本 `details`，例如预约时段和面试官。事件发生时间、预约时间和记录更新时间分别表达。
3. **兼容旧记录且不猜关联**：旧字段缺失仍可读取。可凭校验通过的来源轮次及结果引用恢复原人岗，再按有效岗位配置／别名归组；不根据自由文本姓名自动绑定，不合并同名异岗。缺失或歧义标“关联待确认”，未确定岗位归“岗位待确认”；明确的工作区事件单独归“工作区事项”。来源失败保留可读内容和错误，不自动解决事项、不重写原 run。
4. **列表先说明对象和问题**：总览保留最多三条待回答／待核对摘要和最近七天最多三条进展。桌面两栏各按内容定高，窄屏纵向排列。全部事项按岗位分组并保留状态筛选；当前到期或阻塞事项、其他待回答、历史待核对依次排列，同级按等待时间稳定排序。只用真实期限和提醒时间判断到期，历史导入时间不制造紧急性。工作区总数不受浏览筛选改变。
5. **详情逐层返回**：进展、关联事项、人选资料共用网页详情能力，支持逐层返回，恢复前一层内容、列表位置、筛选及焦点；证据、来源和更正历史按需展开。任务名称由类型、创建时间和可靠对象组成，只有同分钟仍重名时加简短序号；完整 ID 放入详情，任务身份与 live／固定选择规则不变。
6. **岗位范围名副其实**：“在招”只含明确在招；“全部”保留全部招聘状态及未知岗位；“我的关注”是按工作区隔离的本机集合，可含任意状态。关注名单在独立面板从全部岗位选择，不修改招聘状态。切范围保留仍有效的岗位选择，范围外选择清除并提示。未知岗位给可点击提醒；成功读取且确实全部在招时解释两个范围为何相同，失败与空集合不作该推断。

## 安装过渡与历史

源码删除不会卸载用户已安装的独立插件、旧工作区副本或开发预览。现行[宿主指引](../../skills/recruit-board/references/hosts.md#原生入口退役与升级)提供按来源停用和升级的步骤，不自动操作未知位置、用户设置或插件缓存。主插件和网页 Skill 保持可用。

旧方案、ADR、发行说明和验收记录保留其当时结论与证据，不批量改写。涉及“原生可选”、原生测试配置和预览脚本的历史内容从本决策起仅用于追溯；当前安装、开发与验收以本 ADR 和现行 Skill 为准。固定 v0.8.0 发行包并未因工作树清理而改变。

## 后果与验收

- 安装回归确认 marketplace 只发布主招聘插件，项目级 Skill 注册仍包含网页看板，无独立原生入口；公共模型、读写及动作行为继续由 Node 测试覆盖，不要求原生宿主引擎。
- 新旧记录混合、来源缺失、同名异岗、结构化字段验证、版本冲突与最后可信缓存继续覆盖；六个执行工作流和定时任务共用记录契约，不增加招聘动作或授权。
- 网页在 320、375、768、1280px 与宽桌面验证浅深主题、筛选、未知提醒、关注面板、逐层返回和键盘操作。静态阅读或 Node 测试不能替代网页实际验收。
- 源码与模板使用隔离的虚构工作区验证。本次不升级真实工作区、不核实真实历史记录、不卸载用户副本，也不包含提交、推送或发布。
