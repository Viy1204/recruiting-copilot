# ADR 0005：候选进展直接来源于档案事件

日期：2026-11-04

状态：按用户“系统性解决今天约面却不见近期进展”的要求实施。

## 问题

现有近期进展只聚合 run.highlights。普通聊天安排面试后即使已更新台账和档案，只要没有创建任务并额外写重点，首页就会静默漏掉这件事。候选详情和首页使用两条独立写入链路，文件可读不代表进展完整。

## 决策

1. 候选面试档案增加带稳定事件 ID、实际发生时间、类型、事实、依据及可选来源任务的“进展记录”表；档案是这一事实的来源。普通聊天也可通过共用 CLI 写入，不为记录事实伪造执行轮次。
2. 总览直接读取已经核实关联的档案事件，与旧任务重点聚合。相同事件 ID 去重，来源分别保留；没有任务的进展可打开人选和原始档案，不生成不存在的任务链接。
3. 发生时间与预约时段分开。只有日期的旧记录明确按日显示，不补造时分秒；不使用文件修改时间、导入时间或将来的面试时间冒充约面发生时间。七天窗口按实际事件／更正时间处理，读取和重启不刷新历史。
4. 旧排期状态明确记载邀约已于某日发出时可只读恢复当日事件，不从计划、预约时间或文件日期推测；已关联档案有面试安排却没有可核对的日期事件时，返回明确的覆盖诊断及原档案入口，不把它解释为“没有新进展”。档案损坏或丢失保留最后可信事件并标记来源异常；同名异岗和未确认的资料不推断关联。
5. 约面流程将写入事件并回读总览纳入完成判据；完成约面任务前检查对应档案事件是否存在。有来源任务的档案事件可同步进入该任务摘要，旧 run 保持原样。其他工作流发生值得关注的状态变化，也使用同一事件入口或旧 highlight，不重复记两套事实。
6. 本轮核实并补录真实工作区遗漏的已发生事件，记录补录依据和时间精度，保留原台账状态、历史任务及实际排期。

## 验收

没有 run 的当日面试事件也进入近期进展；重复写入和刷新不重复，旧事件不因导入变新；取消改期保留原事件；同名异岗不混淆；缺日期、源文件失败有可见诊断。首页点击可以到来源档案与候选详情。虚构数据回归通过后备份升级真实工作区，实际验证遗漏事件可达。
