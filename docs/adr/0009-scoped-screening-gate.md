# ADR 0009：按岗作用域编译与确定性硬门槛预筛（`screen-gate.mjs`）

日期：2026-11-27

状态：提案实施中。

## 问题

随着工作区在招岗位数量增加（例如同时在招 10–20+ 个岗位），每次筛选单个岗位的简历都让大模型通读整份 `CONTEXT.md` 与所有岗位口径会带来两个根本问题：

1. **O(N) 上下文污染与跨岗串台**：筛选 A 岗候选人时把 B–Z 岗的年龄线、薪资线、学历例外全部灌入上下文，不仅成倍浪费 token，还容易导致大模型张冠李戴（把 B 岗门槛套到 A 岗）。
2. **用概率语言模型重复算确定性条件**：年龄、学历层次、是否统招全日制、院校黑名单/等价层次、工作年限、期望薪资、空白期、跳槽频次与连续工龄豁免、活跃度、城市等纯客观硬门槛，完全可以由代码确定性求值；依赖大模型在长文档里每次现读现算既慢又不稳。

## 决策

1. **采用「统一规则（`defaults`）+ 单岗差异（`roles[role]`）」两层继承模型（`_shared/screening-rules.json`，`schemaVersion: 1`）**：
   - `defaults` 声明全岗位通用硬规则；
   - `roles[roleKey]` 仅填写与统一规则不同的差异项（Delta），未填写的字段自动继承 `defaults`；支持显式写 `null` 放宽某条全局规则（例如某岗取消全局年龄上限）。
   - 支持按固定岗位 ID 或标准岗位名匹配；若工作区同时存在 `_shared/roles.json`，自动复用其名称/ID 与 `internalPath` 映射，但彼此不强耦合。
2. **由脚本控制单岗作用域打包（`screen-gate.mjs pack --role <岗>`）**：
   - 将过去 O(N) 的整文件通读收敛为 **O(1) 单岗编译上下文**：只抽取 `CONTEXT.md` 中的全局政策段落（剔除多岗总表与历史决策），合并**仅本岗的生效规则**（附每项来源 `default` / `role-override` / `relaxed-by-role`），并只读取**本岗这一份** `01-jd/_internal/<role>.md`。
3. **确定性硬门槛预筛与批量过滤（`evaluate` / `evaluate-batch`）**：
   - 只覆盖无歧义的客观可算维度，输出明确三态：
     - `REJECT_HARD_GATE`：命中客观硬门槛，返回精确 `failedRules[]`（规则名、来源、期望值、实际值、原因），直接拦截，无需消耗大模型深评；
     - `PASS_HARD_GATES`：客观硬门槛全部通过，连同 `pack` 生成的单岗精简上下文交给大模型做命脉技能与项目深度评估；
     - `NEED_DETAIL`：无规则否决但存在缺失字段（如列表卡片缺年龄），提示拉取完整简历或交人工核对。
   - 不试图把主观语义判断（命脉经验真伪、跨行迁移价值）硬塞进复杂 DSL。
4. **零依赖、完全向后兼容**：不修改 `model.mjs`、`reader.mjs` 或 `roles.mjs` 等 12 个形式化验证覆盖文件；未配置 `_shared/screening-rules.json` 的工作区不受影响。

## 验收

- 单岗规则正确继承 `defaults`、单岗覆写与显式 `null` 放宽；合并后出现区间倒挂（如 `minAge > maxAge`）直接报校验错误。
- `pack --role <岗>` 仅加载全局政策 + 该岗生效规则 + 该岗一份对内笔记，不包含其他岗位规则与历史决策。
- `evaluate` / `evaluate-batch` 正确覆盖全部客观维度（含分学历年限、院校等价/黑名单、连续工龄跳槽豁免）并返回精准三态与原因。
- 既有全部单测、安装测试与形式化验证基线零破坏。
