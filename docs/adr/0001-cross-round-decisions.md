# ADR 0001：跨轮事项独立于招聘任务轮次

日期：2026-11-04

状态：已接受，用户已确认 [完整方案](../plans/recruit-board-rounds-and-decisions.md) 的 Q1–Q21。展示方式后续由 [ADR 0002](0002-board-progressive-disclosure.md) 简化。下文当时的“网页与原生共用”交付方式由 [ADR 0003](0003-web-only-board.md) 的单网页决定替代；本决策的存储、决定／执行分离及来源追溯语义保持有效。

## 背景

现有任务结果保存在单个 run 中，首页确认名单跟随所选轮次。旧轮次文件仍在，但新轮次会替换首页名单；终态 run 禁止继续修改，无法表达用户在任务结束后作出的决定。

招聘决定有比任务更长的生命周期。同一个岗位问题可以连续多轮被发现，也可以在别的会话里得到答复。批准一个动作还不代表它已经执行成功。

## 决策

保留 run 记录某轮的步骤和事实，增加独立的工作区事项记录。事项通过稳定身份和来源引用关联多个 run；用户答复、暂缓、修订、关闭及后续动作更新事项，不重开或改写终态 run。

事项的决定状态与执行状态分别表示。待用户确认、已暂缓、历史待核对、已决定待执行及处理历史都可从面板查看。状态变更保留版本和历史；写入原子化，旧版本更新被拒绝，重试不会重复产生记录或动作。网页与原生共用同一数据与读写入口。

工作流在核实事实后显式写入重点。最近一轮完成状态与近期重要进展分别展示，明确的“无变化”不会覆盖前面的有用进展；无记录和读取失败不能解释为无变化。

聊天是决策入口，面板是同步视图。岗位标准继续以 `CONTEXT.md` 为准，台账和候选档案保留原有职责；事项记录不是另一套标准。决定后需要同步资料或执行动作时分别记录完成情况，未完成动作保留入口，并在后续授权范围内核查续办。

## 兼容与边界

- 本决策调整 [首屏减负](../plans/recruit-board-focus.md) 中“不引入跨轮待办”的旧范围，历史文档保留其当时结论。
- 旧 run 继续可读。旧 decision 收据没有充分处理证据时作为“历史待核对”，不猜测当前是否仍有效；引入保留来源且可重复执行。
- 沿用工作区本地文件与脚本，不引入数据库、账号系统、常驻调度服务或网页平台操作。
- 普通聊天处理旧事项不伪造完整招聘轮次；主动、定时任务使用相同协议，并注明实际触发来源。
- 只有真实外部操作核实成功才记录完成。授权范围与有效期、只读巡检限制保持不变。
- 提醒限面板和任务摘要；应用关闭期间到期的事项在下次打开时恢复提醒，不自动批准或执行。

## 后果与验收

增加了一份需要随工作区备份的事项数据。工作流必须读写共享入口，不能只在聊天里口头宣布决定已经记录。不同文件的部分成功要显式暴露；面板读取失败时显示最后可信状态与错误。

验收必须证明：五轮相同问题仍是一条；原 run 结束后可决策；刷新与重启不丢事项；已决定未执行有入口；旧写入不能覆盖新决定；无变化巡检保留重要进展；真实数据未参与源码验收。
